REGION DEM -> BICTR .BDEM: GENERATION AND VALIDATION
=====================================================
Date: 2026-11-16
Script: files/make_region_bdems.py
Output: files/atlas_v2/bundle/context/regions/<Region>__dem.bdem (next to each <Region>__dem.tif)


1. WHY THIS WAS NEEDED
----------------------
- OAI's BICTR_LUNAR channel (openair1/SIMULATION/TOOLS/bictr_channel.c, bictr_dem_load) only
  reads its own BDEM format: a regular longitude/latitude grid of float32 heights. It cannot
  read GeoTIFFs.
- The atlas region DEMs (atlas_v2/bundle/context/regions/*__dem.tif) are 20 m/pixel GeoTIFFs in
  south polar stereographic metres, so they must be reprojected, not just converted.
- Before this, only terrain/08_Haworth.bdem existed, and it covers only part of the Haworth tile
  (lon -29.5..-17.9, lat -87.08..-86.42; the TIFF spans lon -42.3..-7.1, lat -87.7..-85.7).
- The fallback terrain/lunar_south_pole.bdem is NOT polar: its header says lat -60..-30,
  lon 0..45 (an SLDEM mid-latitude tile). bictr returns 0 m height outside a DEM, so every other
  region was silently simulated on flat terrain.


2. BDEM FORMAT (as read by bictr_dem_load / bictr_dem_get_height)
-----------------------------------------------------------------
Little-endian:
    b"BDEM"                                        4 bytes magic
    int32 n_lon, int32 n_lat                       grid size
    float64 min_lon, max_lon, min_lat, max_lat     bounds (grid points sit exactly on them)
    float32 heights[n_lat][n_lon]                  row 0 = min_lat, column 0 = min_lon, metres
Pixel size = (max - min) / (n - 1). bictr interpolates bilinearly between grid points.


3. HOW THE CONVERSION WORKS
---------------------------
For each <Region>__dem.tif:
  1. Read heights and georeference with the project's own GeoTIFF reader (raster._geotags).
  2. Find the lon/lat extent with raster.raster_lonlat_extent (64 x 64 edge samples).
  3. Build a lon/lat grid with ~20 m spacing:
       - latitude step  = 20 m / (R * pi/180)                  (~30.3 km per degree)
       - longitude step = 20 m / (R * pi/180 * cos(mid lat))   (1 deg lon shrinks toward the pole)
       R = BODY_RADIUS_M = 1,737,400 m
  4. Project every grid point to stereographic x, y with the same formulas as
     geo_math.lonlat_to_xy, and sample the TIFF bilinearly between pixel centres.
  5. Grid points outside the TIFF (corners of a lon/lat box around a stereographic tile) take the
     nearest edge height, so the file never contains NaN.
  6. Write to <name>.part, then rename, so an interrupted run never leaves a half-written file.

Run:
    cd files
    python3 make_region_bdems.py              # all regions (skips files that exist)
    python3 make_region_bdems.py Haworth      # selected regions
    python3 make_region_bdems.py --force      # rebuild

5. CODE CHANGES
---------------
- make_region_bdems.py (new): the converter above.
- catalog.py, lunar_site_planner.py: find_bdem() looks for <Region>__dem.bdem in the region
  folders; the terrain/ search and the lunar_south_pole.bdem fallback were removed.
- plans.py: make_bulk_run() uses find_bdem(plan["region"]) when that file exists, else the
  plan's stored path; the DEM used is recorded per plan in manifest.json.
- settings.py, lunar_site_planner.py: TERRAIN_DIR and POLE_BDEM marked legacy/unused.
- .gitignore: files/atlas_v2/**/*.bdem (the TIFFs are tracked; these files can be regenerated).


6. KNOWN LIMITATIONS
--------------------
- Connecting_Ridge contains the pole, so its grid spans every longitude. Heights are correct,
  but bictr draws line-of-sight paths as straight lines in lon/lat: a link crossing the +-180 deg
  line or passing very close to the pole follows the wrong path over the terrain.
- Longitude spacing is set at each region's middle latitude, so cells are a little finer than
  20 m on the poleward side and a little coarser on the other side.
- Not yet checked inside OAI: a bictr run should log
  "[BICTR] DEM loaded: .../<Region>__dem.bdem (n_lon x n_lat, lon [..] lat [..])"
  and "DEM terrain mode" instead of "DEM load failed, falling back to flat terrain".
